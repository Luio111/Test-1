# Testplan M2 – Zwischenablage, Datenschutz-Abfragen, Universal Clipboard

Ziel: Das Mitlesen der Zwischenablage funktioniert auf deinem macOS zuverlässig, ohne Systemdialoge und datenschutzkonform.

## Automatisch geprüft (CI, bei jedem Push)

Diese Punkte prüft der Selbsttest auf einem Mac von GitHub. Du musst sie nicht wiederholen:

- Eine Kopie erscheint im Verlauf, mit Formaten und Quell-App.
- Kopien mit `ConcealedType` (Passwortmanager) oder `TransientType` werden **nicht** gespeichert.
- Kopien aus ignorierten Apps und während einer Pause werden nicht gespeichert.
- Bilder (TIFF wird zu PNG), Dateien als Verweis und Farben werden erkannt.
- Eine iPhone-Kopie (Typ `com.apple.is-remote-clipboard`) wird zuerst nur als Platzhalter erfasst. Den Inhalt liest CopyPal erst, wenn du sie auswählst.
- „Nur auf diesem Mac“ setzt `.currentHostOnly` und die Concealed-Markierung (Package-Test auf privater Zwischenablage).
- Ein Bild mit etwa 20 MB blockiert die Oberfläche nicht.

## Vorbereitung

- [ ] `git switch claude/amazing-volta-1uce5i && git pull`, dann `cd CopyPal && ./scripts/bootstrap.sh`, in Xcode ⌘R
- [ ] Menüleiste → Entwicklung → **Labor …** öffnen, Abschnitt „Zwischenablage (M2)“

## Checkliste

| # | Schritt | Erwartet | ✓ |
|---|---|---|---|
| 1 | Text in TextEdit, Safari und Notizen kopieren | Jede Kopie erscheint im Labor mit Formaten, Quell-App, Größe und Lesedauer | |
| 2 | Ein Passwort aus **1Password**, **Bitwarden** und der **Passwörter-App** kopieren | Labor: „übersprungen: als geheim markiert“ oder „App wird ignoriert“. Ergebnis je App notieren. | |
| 3 | Am iPhone Text kopieren (Universelle Zwischenablage an, gleiche Apple-ID) | Labor: „vom iPhone (Inhalt erst bei Auswahl)“. Es erscheint **kein** „Einfügen vom iPhone …“. | |
| 4 | Labor → „iPhone-Kopien: Sofort lesen“, am iPhone erneut kopieren | Wird gelesen. Notieren, ob „Einfügen vom iPhone …“ erscheint. | |
| 5 | Labor → „Nur Typen (ignorieren)“, am iPhone kopieren | „übersprungen: iPhone-Kopien ignoriert“ | |
| 6 | Labor → „Normal schreiben“, am iPhone einfügen | Der Testtext kommt am iPhone an | |
| 7 | Labor → „Nur lokal schreiben“, am iPhone einfügen | Der Testtext kommt **nicht** an | |
| 8 | Diagnose → „Zugriff für CopyPal“ notieren. Zum Testen auf „Fragen“ stellen und etwas kopieren. | Notieren, ob Dialoge erscheinen. CopyPal pausiert dann sichtbar (Menüleisten-Symbol ⚠︎, Menüeintrag „Zugriff auf die Zwischenablage erlauben …“). | |
| 9 | Wieder auf „Immer erlauben“ stellen | Der Weg dorthin ist notiert (Systemeinstellungen → Datenschutz & Sicherheit → …) | |
| 10 | Einen Arbeitstag mit laufendem Labor | Aktivitätsanzeige: CPU etwa 0 %, Energieauswirkung „niedrig“ | |
| 11 | 5K-Screenshot (⌘⇧⌃4) und 50 MB Text kopieren (`yes CopyPal \| head -c 50000000 \| pbcopy`) | Die Oberfläche friert nicht ein. Der Text wird als „zu groß“ übersprungen. | |

## Rückmeldung

Als Kommentar im Pull Request: Checkliste, Ergebnis je Passwortmanager, iPhone-Verhalten je Modus, `accessBehavior`-Wert und **Labor → „Bericht kopieren“**. Der Bericht enthält nur Formate und Größen, keine Inhalte.
